# 고정지출 — Plan → Do → Check → Act

## Plan
월 단위 예정 항목(이름/금액/납부일/지출·결제 계정/기간)을 등록한다. 규칙은 적용 월별로 보존하고 이미 처리한 달은 당시 예정정보를 유지한다. 납부 확인 시 실제 날짜·금액으로 거래를 원자적으로 생성하거나 기존 단순 지출 거래를 연결한다. 이번 달 건너뛰기/처리 취소를 지원한다. 취소는 연결만 해제하고 원장 거래는 삭제하지 않는다. 삭제된 거래는 확인 필요, 복구 시 원래 연결로 회복한다. 예정액은 통계와 예산에 합산하지 않는다. 실제 거래는 기존 집계를 그대로 사용한다.

household 잠금, revision 검사, 항목+월/거래 연결 유일성, RLS를 적용한다. 개인회생/대출 원금/이체는 기존 메뉴를 사용한다. 자동 결제·스케줄러·알림 발송은 범위 밖이다.

## Check
월말/버전/중단/집계, 수정·삭제·복구, 동시성·RLS·원자성, 모바일 입력/오류/재조회, 기존 회귀.

- 실제 PostgreSQL 15 검증 175개 통과(기존 137+신규 38): 원자적 거래 생성·정확한 잔액·기존 이력, 연결 유일성·취소·삭제·복구, 월별 규칙 보존, 계정 보관·입력 오류, 역할/RLS, 실패 시 거래·기록 미생성.

## Act / 운영 반영
기존 001~003이 적용된 Supabase에 004 SQL만 먼저 실행하고 PR을 병합하여 Vercel 배포한다. 원격 DB 인증정보가 없어 운영 SQL과 운영 배포는 미실행이다. 테스트 bootstrap은 운영에 실행하지 않는다.

이미 처리한 달은 당시 예상금액/계정/날짜를 유지한다. 실제 거래 금액을 수정하면 납부액에 반영되고 계정 또는 미래 날짜로 바꾸면 확인 필요로 표시한다. 처리 취소는 기존 거래를 보존하므로 재생성 대신 연결을 권장한다. 자동 스케줄러/은행 결제/개인회생 이중 입력 자동화는 추가하지 않았다.
