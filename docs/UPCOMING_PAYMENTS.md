# 이번 달 예정액과 개인회생 거래 연결

## Plan
대시보드에서 현재 월 미처리 고정지출과 계획별 남은 변제금·납부일을 보여준다. 단순 합계는 예정액이며 가용 현금으로 표시하지 않는다. 개인회생 화면에서 저장된 회차에 새 거래를 원자적으로 생성하거나 기존 지출 거래를 연결한다. 부분 납부와 선납을 지원하고 회차 예정액을 초과하지 않는다. 기존 수동 납부 기록은 보존한다.

연결된 납부 기록은 일반 일정 편집에서 변경하지 못하도록 서버에서 보호한다. 연결 해제 시 납부 기록만 제거하며 거래는 보존한다. 거래 변경·삭제 시 확인 필요로 표시하며 새 납부를 막아 중복을 방지한다. 한 거래를 고정지출과 개인회생에 동시에 연결하지 못하도록 DB에서 검사한다.

## Do
- 대시보드 ‘이번 달 남은 납부’에 현재 월 미처리 고정지출과 각 계획 회차의 잔액·납부일을 표시한다.
- 개인회생 카드의 ‘납부 완료 · 거래 연결’을 펼쳐 회차, 지출 항목, 출금 자산을 선택한다. 새 거래 또는 기존 거래를 연결하며 부분 납부를 지원한다.
- 연결 기록 해제는 확인 후 납부 기록만 제거한다. 거래는 유지한다. 수동 기록도 계속 사용할 수 있다.
- 연결 거래 변경·삭제 시 확인 필요로 표시하고 새 납부를 차단한다. 변제금 합계는 저장된 납부 기록 기준이며 자동으로 바꾸지 않는다. 연결 해제 후 정정된 거래를 다시 연결한다.
- 이미 수동 기록한 납부를 새로 연결하면 중복이므로 해당 수동 기록부터 정정한다.

## Check
- `npm run typecheck`, `npm run build`: 통과.
- `npm run test`: 21개 통과.
- `npm run test:ui`: 6개 시나리오 통과. 모의 Supabase HTTP 환경으로 실제 화면 입력·저장·연결·해제·320px 너비를 검증했다.
- 빈 PostgreSQL 검증 DB에서 bootstrap 및 001~005 마이그레이션을 순서대로 적용했다. 기존 개인회생 32개, 고정지출 38개, 신규 연결 17개, 총 87개 DB 검사를 통과했다.
- 신규 DB 검사는 초과 납부 전체 롤백, 오래된 revision, 중복 연결, 연결 기록 보호, 거래 보존, 고정지출 중복 연결, 삭제된 거래 처리 차단, 타 가계부 접근 차단을 포함한다.
- 모바일 대시보드 캡처 직접 확인. 실제 Supabase 인증·이메일·운영 데이터는 미검증이다.

1. 운영 Supabase SQL Editor에서 `supabase/migrations/202610010005_repayment_transactions.sql` 전체를 실행한다. 001~004가 이미 적용된 프로젝트가 대상이다. 005는 한 번만 실행한다.
2. GitHub PR을 병합하고 연결된 Vercel 배포를 확인한다.
3. 두 사람의 기존 일정과 고정지출을 확인한다. 개인회생 지출 항목이 없다면 ‘자산과 계정’에서 지출 항목을 추가한 후 납부 시 선택한다.
4. 아직 기록하지 않은 납부는 ‘새 거래와 함께 기록’, 이미 가계부에 기록한 거래는 ‘기존 거래 연결’을 사용한다.
